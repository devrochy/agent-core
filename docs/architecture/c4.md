# Diagramas C4 de solvershub

La fuente es [`workspace.dsl`](workspace.dsl) (ADR-0189). **Los bloques Mermaid de este archivo
se generan: no se editan a mano.** Para cambiar un diagrama se edita el modelo y se regenera:

```bash
docker run -d --name structurizr-mcp -p 127.0.0.1:3333:3000 -e PORT=3000 structurizr/mcp:2026.04.20 -dsl -mermaid -plantuml
```

```bash
python scripts/export_c4.py
```

Para ver el modelo de forma interactiva, usar la imagen `structurizr/structurizr` con el
comando `local`, sobre una copia del directorio porque escribe archivos propios en él.

Modelo leído de `develop` el 2026-11-08. El estado de cada elemento (solo en test, sin activar,
en retiro u objetivo) está en su descripción y en sus etiquetas dentro del modelo.

## Preguntas abiertas

- **Ruta de la app en producción.** `solvershub-apk/eas.json:49` apunta a
  `app.solvershub.site/api/pack/pack_cobranza`, y `docs/despliegue-coolify.md:94-96` dice que esa
  ruta no es pública en producción todavía.
- **Publicación de la landing.** Tiene contenedores en test y en producción heredada, pero el
  repo no documenta qué túnel publica el dominio raíz y `www`.

## Invariantes visibles en el diagrama

- **Aislamiento**: cada punto de entrada entra por `tenant_scope` → `set_config`
  (`app.tenant_id`, transacción) → RLS. El runtime conecta como `app_runtime` (no
  dueño); migraciones/bootstrap como el dueño (`MIGRATIONS_DATABASE_URL`).
- **Enablement por tenant**: `spec.packs` (ADR-0019) filtra skills/guardrails/
  eventos/crons y el consentimiento de tools.
- **Cero prompts en código**: prompts en `AgentSpec` (BD) y playbooks del pack
  (allowlist). Copy en config por tenant.
- **Contratos congelados**: `packages/contracts` inmutable (ADR-0011).
- **Packs independientes**: ningún pack importa de otro (`.importlinter`).
- **Billing de plataforma**: el cobro usa credenciales propias de la plataforma, nunca
  las del tenant (ADR-0046).
